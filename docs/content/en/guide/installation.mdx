# Installation

<Callout type="info">
  Echo UI **`1.1.x`** supports Tailwind CSS 4 and 3. Tailwind CSS 4 is the recommended path for new
  projects. The published Echo UI **`1.0.0`** build remains Tailwind CSS 3-only. Echo UI `1.1.x`
  also supports matching React and React DOM versions from React `18.2` through React `19`.
</Callout>

## 1. Compatibility and requirements

The `1.1.0` package is tested as an installed, packed dependency with Tailwind CSS `4.3.3` and `3.4.19`. Both fixtures compile representative controller, container, and visualization components from the published `dist` files, then compare their computed light and dark styles in Chromium.

| Echo UI | Tailwind CSS | tailwind-variants | tailwind-merge | Support |
| --- | --- | --- | --- | --- |
| `1.1.x` | `4.3.x` | `3.2.x` | `3.6.x` | Recommended and tested |
| `1.1.x` | `3.4.x` | `3.2.x` | `3.6.x` | Supported and tested |
| `1.0.0` | `3.3.5` | `0.1.x` | `2.x` | Legacy published build; not in the automated matrix |

The Tailwind packages are build-time dependencies in your application. Echo UI installs the listed `tailwind-variants` and `tailwind-merge` versions itself.

## 3. Configure Tailwind CSS

### Tailwind CSS 4 (recommended)

<Steps>

### Install Tailwind's Vite integration

```bash
pnpm add -D tailwindcss@^4.3.3 @tailwindcss/vite@^4.3.3
```

### Add the Vite plugin

```ts filename="vite.config.ts"
import tailwindcss from '@tailwindcss/vite'
import react from '@vitejs/plugin-react'
import { defineConfig } from 'vite'

export default defineConfig({
  plugins: [react(), tailwindcss()],
})
```

### Import Tailwind and discover Echo UI classes

Import the CSS-first Echo UI theme and explicitly scan the installed distribution. Tailwind ignores dependency folders by default, so the `@source` line is required when your app compiles Echo UI's utility classes.

```css filename="src/index.css"
@import 'tailwindcss';
@import '@nafr/echo-ui/theme.css';
@source '../node_modules/@nafr/echo-ui/dist';
```

### Render a component

```tsx filename="src/App.tsx"
import { Knob } from '@nafr/echo-ui'
import './index.css'

export default function App() {
  return <Knob />
}
```

</Steps>

`theme.css` contains the maintained light and dark tokens, the class-based dark variant, and Tailwind 4's CSS-first color and radius mappings. Override any `--echo-*` variable after this import to customize the theme.

### Tailwind CSS 3

Use this path when an existing application cannot move to Tailwind 4 yet.

<Steps>

### Install the Tailwind 3 toolchain

```bash
pnpm add -D tailwindcss@3.4.19 postcss@8 autoprefixer postcss-import
```

### Configure PostCSS

`postcss-import` must run before Tailwind so the published Echo UI theme variables are included.

```js filename="postcss.config.js"
export default {
  plugins: {
    'postcss-import': {},
    tailwindcss: {},
    autoprefixer: {},
  },
}
```

### Configure content discovery and theme tokens

```js filename="tailwind.config.js"
/** @type {import('tailwindcss').Config} */
import { theme } from '@nafr/echo-ui/tailwind-theme'

export default {
  content: ['./src/**/*.{js,ts,jsx,tsx}', './node_modules/@nafr/echo-ui/dist/**/*.{js,cjs}'],
  darkMode: ['class'],
  theme,
}
```

### Import the theme and Tailwind layers

```css filename="src/index.css"
@import '@nafr/echo-ui/theme.css';

@tailwind base;
@tailwind components;
@tailwind utilities;
```

Use the same component import shown in the Tailwind 4 path.

</Steps>

## 4. Import and render components

Import the component and the application stylesheet that contains your selected Tailwind setup:

```tsx filename="src/App.tsx"
import { Knob } from '@nafr/echo-ui'
import './index.css'

export default function App() {
  return <Knob />
}
```

## Migrate from Tailwind CSS 3 to 4

1. Replace the Tailwind/PostCSS plugin setup with `tailwindcss@^4.3.3` and `@tailwindcss/vite@^4.3.3`.
2. Remove the Echo UI `content` and `theme.extend` blocks from `tailwind.config.js`.
3. Replace the three `@tailwind` directives with the Tailwind 4 `@import` and Echo UI `@source` block above.
4. Keep custom `--echo-*` overrides after `@import '@nafr/echo-ui/theme.css';`.
5. Check application-owned utilities against Tailwind's [upgrade guide](https://tailwindcss.com/docs/upgrade-guide): Tailwind 3's `shadow-sm` maps to `shadow-xs` in Tailwind 4, `outline-none` maps to `outline-hidden`, and scale animations must include `scale` in custom `transition` property lists. Default border, ring, radius, and palette semantics also changed.

Echo UI `1.1.x` normalizes these changed utilities inside the component package. Run `pnpm test:tailwind-compat` in this repository to rebuild both installed-consumer fixtures and repeat the computed-style regression check.

The maintained sources are [`packages/theme.css`](https://github.com/codeacme17/echo-ui/blob/main/packages/theme.css), [`packages/tailwind-theme.ts`](https://github.com/codeacme17/echo-ui/blob/main/packages/tailwind-theme.ts), and [`packages/index.css`](https://github.com/codeacme17/echo-ui/blob/main/packages/index.css).
